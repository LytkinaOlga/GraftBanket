# Draft Catering — сайт

Локальный прототип сайта: примеры существующих боксов, демонстрационный конструктор закусок и серверная функция заявок в Telegram. Названия, составы, цены и правила количества в конструкторе пока заглушки. Готовые боксы показаны фотографиями без неподтверждённых цен и составов.

## Структура

- `index.html`, `css/styles.css`, `js/data.js`, `js/app.js` — сайт (каталог, корзина, форма заявки).
- `api/order.js` — серверная функция (формат Vercel Serverless Functions), принимает POST-заявку и шлёт сообщение в Telegram Bot API.
- `js/data.js` — данные о блюдах. Сейчас там заглушки (сгенерированные названия/цены/фото). Чтобы заменить на реальный контент — редактировать этот файл: имя, вес, цена, состав, описание, ссылка на фото (`img`) для каждой позиции.

## Локальный просмотр

Из папки `site/` запустить Node.js-сервер:

```
node dev-server.js
```

Открыть `http://127.0.0.1:8080`. Этот сервер обслуживает также `/api/order`. Для отправки в Telegram нужны `TELEGRAM_BOT_TOKEN` и `TELEGRAM_ADMIN_CHAT_ID` в `.env.local` (файл исключён из публикации). Не отправляйте реальные заявки с демонстрационными позициями.

## Тестирование отправки заявки в Telegram

Есть три уровня проверки — от самого быстрого к самому полному.

### 1. Проверить, что бот вообще может писать (без сайта)

Самая быстрая проверка — убедиться, что токен и chat_id верные, ещё до возни с хостингом. Вставить в адресную строку браузера (подставив свой токен):

```
https://api.telegram.org/bot<ВАШ_ТОКЕН>/sendMessage?chat_id=<CHAT_ID>&text=Тестовое+сообщение
```

Если всё верно — в браузере появится `{"ok":true,...}`, а в Telegram придёт сообщение «Тестовое сообщение». Если ошибка — значит проблема в токене/chat_id, а не в коде сайта.

### 2. Локально через Vercel CLI (полноценный тест до деплоя)

Понадобится Node.js и бесплатный аккаунт на vercel.com.

```
npm i -g vercel
cd site
vercel dev
```

При первом запуске `vercel dev` попросит войти в аккаунт и привяжет папку `site/` к проекту — значения из `.env.local` (уже лежит в папке) подхватятся автоматически. Дальше открыть выданный локальный адрес (обычно `http://localhost:3000`), пройти каталог → корзина → заявка → отправить. Сообщение должно прийти в тот же Telegram-бот.

### 3. На реальном хостинге (после деплоя)

1. Зарегистрироваться на vercel.com (можно через GitHub).
2. Загрузить содержимое папки `site/` в новый репозиторий на GitHub (или воспользоваться Vercel CLI: `vercel` из папки `site/`, без GitHub тоже можно).
3. В Vercel создать новый проект из этого репозитория/папки — `site/` должна быть корнем проекта.
4. В Project Settings → Environment Variables добавить:
   - `TELEGRAM_BOT_TOKEN` — токен бота
   - `TELEGRAM_ADMIN_CHAT_ID` — chat_id администратора (или несколько через запятую, см. ниже)
   (значения — в `.env.local`, не публиковать их в коде/репозитории)
5. Задеплоить (`vercel --prod` или через дашборд) — Vercel автоматически распознает `api/order.js` как серверную функцию.
6. Открыть выданный `*.vercel.app` адрес, пройти заказ до конца, проверить Telegram.
7. Домен подключить позже через Project Settings → Domains, когда будет куплен.

## Несколько администраторов

`api/order.js` рассылает заявку всем chat_id, перечисленным в `TELEGRAM_ADMIN_CHAT_ID` через запятую, например:

```
TELEGRAM_ADMIN_CHAT_ID=979287967,123456789
```

Чтобы добавить нового администратора:

1. Новый администратор узнаёт свой chat_id — например, через **@userinfobot** в Telegram (написать `/start`, бот пришлёт числовой ID).
2. Новый администратор открывает бота Draft Catering и пишет ему `/start` или любое сообщение — без этого Telegram не даст боту написать первым (ошибка `chat not found`).
3. В значение `TELEGRAM_ADMIN_CHAT_ID` дописывается новый ID через запятую — и в `.env.local` (для локальной разработки), и в Vercel → Project Settings → Environment Variables.
4. После изменения переменной на Vercel обязательно передеплоить проект (Deployments → «...» на последнем деплое → Redeploy) — иначе новое значение не подхватится.
5. Если у одного из администраторов что-то не доставится (например, устаревший ID) — заявка всё равно будет принята для остальных, а ошибка попадёт в Vercel → Deployments → Logs.

## Важно

- `.env.local` — только для локальной разработки (`vercel dev` читает его автоматически). В облачный хостинг эти значения переносятся вручную через переменные окружения в дашборде. Файл не должен попадать в публичный репозиторий (см. `.gitignore` в этой папке).
